# Pothos GraphQL Schema Modularization

> Reusable skill for organizing Pothos GraphQL schemas into domain-based modules

## Overview

This skill provides patterns for reorganizing flat Pothos schema files into modular, domain-driven structures. Each domain module contains types, queries, mutations, and subscriptions co-located by business domain.

## Context

- **Framework**: Pothos GraphQL with TypeScript
- **Plugins**: @pothos/plugin-relay, @pothos/plugin-dataloader, @pothos/plugin-scope-auth
- **Target**: Domain-driven modular schema organization
- **Client**: urql with codegen

## Key Patterns

### 1. Domain Module Structure

Each domain gets its own directory:

```
packages/frameworks/src/graphql/
├── builder.ts           # Pothos builder configuration
├── schema.ts            # Central schema assembly point
├── index.ts             # Public exports
├── context.ts           # GraphQL context
├── errors.ts            # Error handling utilities
├── auth.ts              # Authorization scopes
├── scalars.ts           # Custom scalars
├── relay.ts             # Relay pagination utilities
├── loaders.ts           # DataLoader utilities
├── server.ts            # Yoga server setup
├── types/
│   ├── index.ts         # Re-exports all domain modules
│   ├── user/
│   │   ├── types.ts     # Object types with Relay interface
│   │   ├── queries.ts   # Query resolvers
│   │   ├── mutations.ts # Mutation resolvers with auth
│   │   ├── subscriptions.ts # Real-time subscriptions
│   │   ├── index.ts     # Module exports and registration
│   │   └── types.test.ts # Co-located tests
│   ├── event/
│   │   ├── types.ts
│   │   ├── queries.ts
│   │   ├── mutations.ts
│   │   ├── subscriptions.ts
│   │   ├── index.ts
│   │   └── types.test.ts
│   └── ...
```

### 2. Module Index Pattern

The `index.ts` in each domain module handles side-effect registration:

```typescript
// packages/frameworks/src/graphql/types/user/index.ts
export { UserType, UserConnectionType } from "./types";
export { userQueries } from "./queries";
export { userMutations } from "./mutations";
export { userSubscriptions } from "./subscriptions";

// Side-effect: Register types with builder
import "./types";
import "./queries";
import "./mutations";
import "./subscriptions";
```

### 3. Schema Assembly Pattern

Central schema.ts imports all domain modules and exports unified schema:

```typescript
// packages/frameworks/src/graphql/schema.ts
import { builder } from "./builder";

// Import all domain modules (side-effect registration)
import "./types/user";
import "./types/event";
import "./types/sponsor";
import "./types/notification";
import "./types/coinTransaction";

// Build and export unified schema
export const schema = builder.toSchema();
export default schema;
```

### 4. Type Definition Pattern (types.ts)

Using all three Pothos plugins effectively:

```typescript
import { builder } from "../../builder";
import type { UserDTO } from "@mirai-app/use-cases";

/**
 * User Type with Relay node interface
 */
export const UserType = builder.node("User", {
  id: { resolve: (user) => user.id },
  description: "A user in the system",
  loadMany: (ids) => userLoader.loadMany(ids), // DataLoader
  fields: (t) => ({
    email: t.exposeString("email"),
    firstName: t.exposeString("firstName", { nullable: true }),
    // ... other fields
  }),
});

/**
 * Connection type (auto-generated by Relay plugin)
 */
export const UserConnectionType = builder.connection(
  {
    name: "UserConnection",
    node: UserType,
  },
  {
    name: "UserEdge",
  },
);
```

### 5. Query Resolver Pattern (queries.ts)

```typescript
import { builder } from "../../builder";
import { decodeCursorWithDate, clampFirst } from "../../utils/connections";
import { UserConnectionType } from "./types";

export const userQueries = builder.queryFields((t) => ({
  users: t.field({
    type: UserConnectionType,
    args: {
      first: t.arg.int(),
      after: t.arg.string(),
    },
    resolve: async (_parent, args, ctx) => {
      const controller = ctx.controllers.userController;
      // ... resolver logic
    },
  }),
}));
```

### 6. Mutation with Auth Pattern (mutations.ts)

```typescript
import { builder } from "../../builder";
import { defineAuthScopes } from "../../auth";

const authScopes = defineAuthScopes((context) => ({
  authenticated: !!context.authContext?.user,
  admin: context.authContext?.user?.role === "admin",
}));

export const userMutations = builder.mutationFields((t) => ({
  updateUser: t.field({
    type: "User",
    authScopes: { authenticated: true }, // Scope Auth plugin
    args: {
      id: t.arg.id({ required: true }),
      input: t.arg({ type: UpdateUserInput, required: true }),
    },
    resolve: async (_parent, args, ctx) => {
      // Mutation logic
    },
  }),
}));
```

### 7. Subscription Pattern (subscriptions.ts)

```typescript
import { builder } from "../../builder";
import type { AsyncIterator } from "graphql-subscriptions";

export const userSubscriptions = builder.subscriptionFields((t) => ({
  userUpdated: t.field({
    type: "User",
    subscribe: async function* (): AsyncIterator<UserDTO> {
      // Subscribe to events
      for await (const event of userEventStream) {
        yield event.user;
      }
    },
    resolve: (payload) => payload,
  }),
}));
```

### 8. Error Handling Pattern

```typescript
import { createGraphQLError, mapDomainErrorToGraphQL } from "../../errors";

// In resolver:
const result = await controller.updateUser({ id: args.id, input });

if (!result.success) {
  throw mapDomainErrorToGraphQL(result.error, context);
}

return result.data;
```

## Plugin Integration

### @pothos/plugin-relay

```typescript
// Use node interface for global IDs
builder.node("User", {
  id: { resolve: (user) => user.id },
  // ...
});

// Connections for pagination
const UserConnection = builder.connection({
  name: "UserConnection",
  node: UserType,
});
```

### @pothos/plugin-dataloader

```typescript
// Use loadable for batched loading
const UserType = builder.loadableNode("User", {
  id: { resolve: (user) => user.id },
  loadMany: (ids, context) => context.loaders.user.loadMany(ids),
  // ...
});
```

### @pothos/plugin-scope-auth

```typescript
// Define auth scopes on builder
scopeAuth: {
  authScopes: () => ({
    public: true,
    authenticated: false,
    admin: false,
  });
}

// Use on fields
authScopes: { authenticated: true, admin: true }
```

## Schema Generation Workflow

1. **Define/Update Pothos Schema**: Edit files in `packages/frameworks/src/graphql/types/`
2. **Generate SDL**: Run script to output to `packages/graphql-client/src/generated/graphql/schema.graphql`
3. **Generate Client**: Run `graphql-codegen` to produce urql hooks
4. **Apps use hooks**: Never import schema directly, only use generated hooks

## Migration from Flat Files

1. Create domain directories
2. Move types to `types.ts` in each domain
3. Extract queries to `queries.ts`
4. Extract mutations to `mutations.ts` (if any)
5. Create `subscriptions.ts` (if needed)
6. Create `index.ts` for exports and side-effect registration
7. Update schema assembly point
8. Verify generated schema matches (no breaking changes)

## Common Pitfalls

1. **Missing side-effect imports**: Ensure index.ts imports all module files
2. **Circular dependencies**: Avoid cross-domain imports within types.ts
3. **Duplicate registration**: Each type should only be registered once
4. **Breaking schema changes**: Keep GraphQL schema compatible during refactor
