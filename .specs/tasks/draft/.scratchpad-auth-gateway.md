## Synthesis - Architecture Overview Structure

### 1. Solution Strategy
- Clean Architecture with Effect DI
- Unified verification (session + resource) at gateway level
- Port naming: IAuthPort (domain), AuthPortTag (use-cases), implements IAuthPort (adapters)

### 2. Component Overview
**Domain Layer:**
- IAuthPort interface with verifyAccess()
- AuthErrors: AuthSessionExpiredError, PermissionDeniedError, TokenMissingError
- AccessCheckRequest type

**Use-Cases Layer:**
- AuthPortTag Context.Tag for DI

**Adapters Layer:**
- SupabaseAuthGateway implements IAuthPort
- Migration of existing gateways (TripDrizzleGateway, UserDrizzleGateway, etc.)

**Frameworks Layer:**
- makeAuthLayer() for Layer composition
- Integration into makeAppLayer()
- Mock auth layer for testing

### 3. Contracts and Interfaces
- IAuthPort.verifyAccess(request: AccessCheckRequest): Effect<void, AuthError, never>
- AccessCheckRequest: { token, resourceType, resourceId, requiredPermission, requireOwnership? }
- Modified gateway signatures: add authToken parameter

### 4. Data Flow
1. GraphQL resolver extracts token from Authorization header
2. Resolver passes token to gateway method via ctx.runWithAppLayer
3. Gateway: yield* AuthPortTag to get auth port
4. Gateway: yield* authPort.verifyAccess({ token, resourceType, resourceId, permission })
5. SupabaseAuthGateway: validate JWT with Supabase Auth
6. SupabaseAuthGateway: check resource permissions via domain tables
7. On success: proceed with data operation; On failure: return auth error
8. Error mapping: AuthSessionExpiredError → 401, PermissionDeniedError → 403

### 5. Integration Points
- GraphQL context: accessToken extraction and passing
- Error mapping: domain errors to GraphQL error codes
- Testing: mock auth layer in test.ts
- Existing DI: Layer.mergeAll with authLayer

### 6. Expected Changes
**Create:**
- packages/domain/src/auth/errors/AuthErrors.ts
- packages/use-cases/src/auth/ports/AuthPort.ts
- packages/frameworks/src/di/layer/auth.ts

**Modify:**
- packages/domain/src/shared/services/index.ts (add verifyAccess to IAuthPort)
- packages/domain/src/index.ts (export auth errors)
- packages/adapters/src/auth/gateways/supabase/SupabaseAuthGateway.ts (implement verifyAccess)
- packages/frameworks/src/di/layer/app.ts (merge auth layer)
- packages/frameworks/src/di/index.ts (export makeAuthLayer)
- packages/frameworks/src/di/layer/test.ts (mock auth layer)

**Migration (existing gateways):**
- TripDrizzleGateway, UserDrizzleGateway, GroupDrizzleGateway, ChallengeDrizzleGateway

**Key Decisions:**
1. Unified verifyAccess vs separate session + permission checks
2. Port naming: I-prefix for domain, Tag suffix for use-cases (no declaration merging)
3. Inference-first return types (no explicit annotations in implementations)
4. Token parameter in gateway methods (not in DI layer - keeps gateways flexible)
5. Phased migration to manage breaking changes

## Risk Mitigation from Analysis
- Breaking changes: Optional authToken parameter, gradual rollout
- Circular deps: Auth gateway queries via Supabase (not direct DB)
- Performance: Cache session validation, use joins
- Test complexity: Mock auth layer utility
- Partial implementation: Document all gateways, type system enforcement
